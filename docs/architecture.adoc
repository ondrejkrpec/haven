= Architecture and implementation boundaries

Haven is intended to run a personal assistant on one Ubuntu VPS. Hermes supplies conversations, a durable Kanban board and scheduling. WhatsApp text and inbound Czech voice messages are the planned phone interface. The coordinator's working name is Nora.

== Current foundation

H0.1 established a candidate based on Hermes v0.22.5 plus an exact upstream patch. Local fake-provider tests and rootless container probes established feasibility. link:../research/h0.1/README.adoc[The report] records versions and limits. H0.2 added this repository and the private-instance template; H0.3 adds link:configuration.adoc[configuration v1 validation]. There is no installed Haven service yet.

Keep common source, general instructions and public examples here. Each instance owns its configuration and personal instructions in a separate private repository. Runtime state, account sessions and databases require a future backup workflow outside Git.

== Controller and executor boundary

The trusted controller owns the durable board and admits narrowly scoped results bound to the current run. A worker and an independent reviewer will run as full isolated executor processes with only their workspace and required role-specific credentials. Neither receives Nora's home, WhatsApp session, personal vault or direct access to the board.

The H0.1 `dispatch_once(spawn_fn=...)` probe uses an internal, version-bound Hermes API. A small adapter with authenticated admission, role authorization and crash-safe receipts remains H2 work. Selecting a container terminal backend does not isolate Python, plugins or the rest of an agent process. Hermes profiles and task status do not enforce deployment authorization.

== Recovery and bounded autonomy

Supervised deterministic dispatch must resume deferred work while Nora's model is unavailable. Use one dispatch owner. Distinguish quota cooldowns from revoked credentials and terminal provider errors. Persistent tasks and idempotent intake do not guarantee exactly-once external effects; reconcile the target after uncertain outcomes before retrying.

Automatic deployment will initially be limited to the proposed `haven-health` demonstration service. An independent runner must enforce the permitted target, exact reviewed commit, health check and rollback policy. General production changes remain outside that permission.
