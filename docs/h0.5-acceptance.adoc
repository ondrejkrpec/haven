== Documented setup and checks

The first shell block in link:configuration.adoc[configuration setup] and the first shell block in link:documentation.adoc[documentation tooling] were extracted from the cloned guides and executed unchanged, in order. Their effective setup was:

[source,sh]
----
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes --only-binary=:all: -r requirements.txt
.venv/bin/python scripts/validate_config.py examples/instance.yaml
.venv/bin/python -m unittest discover -s tests -v
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes --only-binary=:all: -r requirements-dev.txt
npm ci --ignore-scripts --no-audit --no-fund
.venv/bin/python -m scripts.install_check_tools
.venv/bin/python -m pip check
.venv/bin/python -m scripts.check
----

Both pip installs used the checked-in distribution hashes and binary-only policy. npm installed from the lock without lifecycle scripts. The binary installer downloaded Gitleaks/actionlint and verified their pinned archive hashes. `pip check` reported no broken requirements. No real credentials or private package registries were needed.

The complete checks passed before any private sibling existed: Ruff, strict yamllint, actionlint, configuration examples, all 23 behavior tests, all 16 retained H0.1 checksums, candidate-file and fixture-history secret scans, the Antora build and offline source/generated links. The initial site had 11 documentation pages plus its root redirect. H0.1 integration experiments were not rerun; their retained evidence was checked for integrity.

== Another private instance

The instance-creation shell block in link:../README.md[README] was executed unchanged in the clone. It created a separate private Git repository from the public template. Its synthetic configuration was edited to use an independent instance name, time zone, reserved example hostname and placeholder model, then checked explicitly:

[source,sh]
----
.venv/bin/python scripts/validate_config.py ../haven-private/config/instance.yaml
.venv/bin/python scripts/validate_config.py examples/instance.yaml \
  --override ../haven-private/config/instance.yaml
----

Both validations passed, and assertions confirmed the edited fields survived defaults/layering. Repeating the README setup exited with status `1` at its existing-destination check; hashes of every file in the synthetic private repository were unchanged. The public clone remained clean.

Ignore checks covered representative dotenv, authentication/session, credential, key and database paths in both repositories. Instance YAML was ignored by the public repository and remained eligible for the private repository. These checks establish the current Git rules, not encryption or runtime access controls.

Next, the synthetic private YAML was deliberately made invalid and given a synthetic marker. Running the complete public checks again still passed. The marker was absent from every generated site file, including attachments. The valid private YAML was restored afterwards. This complements the maintained tests for symlinks, escaping paths, undeclared targets and ignored inputs; it does not grant executors access to private data.
