= H1.6 Agent Platform compatibility assessment

Assessment date: 2026-10-29. This is a local review of a candidate community connector for the link:family-conversations.adoc[selected personal/family design]. No plugin was installed into the pilot, no real API key was used and no live WhatsApp/model request was made.

Later owner decision on the same date: Agent Platform is unavailable on their account. This assessment is retained as historical evidence; the current first integration is link:h1.6-telegram.adoc[owner-only Telegram]. No WhatsApp release date is assumed.

== Exact inputs

* Hermes v0.22.5, commit `bf0203a794a07aac3ff764972ab9087baa4e4f4e`, with the attributed upstream recovery patch recorded in link:../research/h0.1/README.adoc[H0.1].
* Community `whatsapp-agent-platform` v0.2.0, commit `4d8fc1c482ed06a34b6609b1dcdf59e370de7d40`, from https://github.com/ahtishamdilawar/hermes-whatsapp-agent-platform[the connector repository]. It is not a Meta or NousResearch implementation. The MIT package declares no extra runtime dependencies; it uses core `httpx`.
* The existing disposable Hermes dev/test environment built through the pinned PM lock, separate from service credentials and production state.

The review covered the plugin manifest, registration, adapter, client, persisted polling state and test fixtures. The adapter resolves a scoped API key, verifies the creator through the API and keeps key-specific cursor/deduplication state below the Hermes home. It has duplicate-key poller guards. These mechanisms do not implement family membership or data authorization.

== Reproduction and result

Use fresh disposable checkouts at the exact revisions above and the PM-built test environment described in H0.1. Apply only the retained recovery patch. Do not install or enable the plugin, run its wizard or supply credentials. From the Hermes checkout, set `HERMES_PYTHON` to that disposable environment's `bin/python` and `HAVEN_AGENT_PLUGIN` to the exact connector checkout, then run:

[source,bash]
----
HERMES_TEST_FILE_RETRIES=0 scripts/run_tests.sh -j 2 \
  "$HAVEN_AGENT_PLUGIN/tests/test_adapter.py" \
  "$HAVEN_AGENT_PLUGIN/tests/test_client.py" \
  "$HAVEN_AGENT_PLUGIN/tests/test_delivery_and_state.py" \
  "$HAVEN_AGENT_PLUGIN/tests/test_state_and_formatting.py" \
  "$HAVEN_AGENT_PLUGIN/tests/test_plugin_load.py" \
  "$HAVEN_AGENT_PLUGIN/tests/test_hermes_compat.py" \
  --file-timeout 90
----

Result: 6 files, 137 passed, 0 failed, no retries. The upstream canonical per-file runner was used. Connector fixtures supplied disposable homes, synthetic keys/identities and mocked HTTP responses. The passing files cover adapter behavior, client requests, delivery/state, formatting, plugin loading and compatibility with the pinned Hermes APIs.

This is a compatibility result. The run did not exercise two live accounts, independently secured runtimes, family objects, cross-user privacy or real API behavior. The test suite's optional extra-sender cases cannot override Meta's creator-only delivery rules.

== Two-connection probe

Haven's retained `research/h1.6/test_agent_connections.py` adds three behavioral scenarios using the real connector adapter/client and Hermes context-local home/secret scopes. HTTP alone is replaced with the connector's mock transport; no model runs.

* Both connections accept the same external message ID independently, retain different creators/cursors, and send through the correct bearer key and recipient even when the caller has the other profile's scope. Restarting the first connection preserves its cursor/deduplication while the second keeps working.
* An API-rejected foreign sender is dropped on each connection before the conversation handoff, including when that sender owns the other connection.
* A second poller using the same key is refused even with a different home; after the first disconnects, that key can reconnect.

Result: 3 passed, 0 failed, no retries. Clone the connector at the exact revision into the ignored Haven path `build/whatsapp-agent-plugin`; verify both checkout revisions before running. Set `HAVEN_ROOT` to the public Haven checkout, then use the same Hermes runner/environment:

[source,bash]
----
HERMES_TEST_FILE_RETRIES=0 scripts/run_tests.sh -j 2 \
  "$HAVEN_ROOT/research/h1.6/test_agent_connections.py" --file-timeout 90
----

This probe establishes scoped adapter behavior in one test process. It does not test gateway-level conversation routing, isolation from arbitrary files/tools, family storage or operating-system access control. Outbound text also needs Haven-side recipient authorization before calling the chosen adapter; the connector delegates arbitrary text-recipient rejection to Meta. Correct transport credentials alone do not authorize a user to access another member's adapter or data.
