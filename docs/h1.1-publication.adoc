= H1.1: GitHub publication and first CI

Status on 2026-10-25: public/private repositories are published with MIT and correct visibility. The owner accepted automatic local push checks in place of unavailable GitHub Actions. Public HTTPS cloning without credentials was verified; successful Actions execution is not claimed.

== Scope and licensing

The public repository contains common source, English documentation, synthetic examples, the private-instance template and retained research evidence. Each installation owns its separate private repository. Local workspaces remain in place; GitHub adds remote history and distribution. Documentation hosting remains H1.8 work.

link:../LICENSE[MIT] covers original Haven material. The copied Hermes patch and research artifacts retain their link:../research/h0.1/UPSTREAM-LICENSE[upstream notice], author metadata and provenance. The private template carries `TEMPLATE-LICENSE` so its notice survives copying. A private instance must stay private and must not supply public build inputs.

== Publication procedure

Before the first push, review the exact Git-eligible candidates, inspect ignore boundaries, validate the instance explicitly and run the public foundation checks. Scan the private source separately, without copying it into public test or documentation inputs. Disposable review indexes can check new files without modifying working indexes.

Use the authenticated owner's account to verify repository names. Create the public project and private instance with their intended visibility, without an extra remote README/license commit. Commit the reviewed local source and configure its matching remote. Record the exact public source revision in the private instance, then commit and push the private instance to its private remote. Preserve local instance edits during template updates.

GitHub authentication uses the official CLI browser flow; tokens and one-time codes are not recorded in project files or reports. Commit metadata uses the owner's identity and GitHub noreply address. No provider credentials, WhatsApp sessions, runtime databases, package caches or generated sites belong in either source publication.

After pushing, verify remote visibility and matching branch revisions, clone the public repository from GitHub without private access and verify retained checksums. Use the configured local push pipeline to check the exact committed HEAD before publication. The private hook also checks its explicit configuration and files/history. Local actionlint success and local pipeline success do not establish GitHub Actions execution.

== Local preparation

The initial publication review covered 71 public files and eight private files, before the MIT license files and these publication updates were added. The private input remained synthetic, passed configuration validation and had no Gitleaks findings. The complete local check command passed, including 23 tests and the retained H0.1 manifest. Those counts describe the initial review, not the final published tree.

The npm documentation shortcut was corrected to run `python3 -m scripts.build_docs`, matching the canonical module invocation. This makes imports work from an activated virtual environment without relying on an inherited Python path. No dependency versions were changed. Extensionless license attachments use `.txt` download aliases so Antora produces file links rather than local fragments; their canonical source names and bytes are preserved.
