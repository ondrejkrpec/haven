= Haven H0.1 evidence

Research performed on 2026-10-25. This directory contains feasibility probes and upstream test results, transferred to Haven during H0.2. It is not an installed Haven instance. Historical logs have local usernames and hostnames replaced; `provenance.json` records original file hashes and transformations. Test counts and failures are retained. The original local archive remains unchanged.

The portable isolation probe now derives the Codex home path and uses a synthetic vault note instead of the author's vault path. Its new execution evidence is separate from the original H0.1 results. Read link:../../docs/local-development.adoc[local development] for the foundation workflow.

H0.2 reran the portable filesystem probe successfully; `evidence/h0.2-portable-isolation.json` records that result. The unchanged dispatcher probe and the upstream suite retain their H0.1 results. `.gitattributes` preserves patch bytes and exempts historical log and patch whitespace from formatting checks.

== Candidate and findings

The baseline is https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.5[Hermes v0.22.5], commit `bf0203a794a07aac3ff764972ab9087baa4e4f4e`. The unmodified release fails the required quota-to-review recovery scenario. A candidate using upstream https://github.com/NousResearch/hermes-agent/pull/117820[PR #117820], commit `36fbe1ebb69340a6de881e7c93aecd5c684a373b`, passes that scenario locally. The PR was open and unmerged at inspection. This is an explicitly patched candidate, not a claim that the released version contains the fix.

The patch skips an obsolete failure stamp after a newer run has progressed. It retains current authentication guards, quota cooldowns and duplicate-work guards. Its original MIT attribution is in the patch and `UPSTREAM-LICENSE`. `pins.json` records hashes. An upstream release containing an equivalent fix can replace the patch only after rerunning the acceptance scenario.

Counts overlap between runs and must not be summed as unique tests. Platform skips are retained in logs. These tests ran on Manjaro Linux, PM Python 3.14.9 and rootless Podman 6.1.0, not Ubuntu. Codex CLI 0.164.0 is locally present; real authenticated Codex inference was not exercised.

The stricter filesystem probe initially allowed a write to `/tmp`: Podman mounts writable temporary filesystems by default even with `--read-only`. The final isolation probe explicitly sets `--read-only-tmpfs=false` and verifies rejection of that write. The dispatch seam probe retains Podman's normal temporary filesystems; neither probe exposes host credentials. See the https://docs.podman.io/en/v6.1.0/markdown/podman-run.1.html#read-only-tmpfs[Podman 6.1 manual].

== Technical path for H1–H2

Use Hermes' durable board for task/run/event state and review handoffs. Keep a trusted controller responsible for claims and narrow result transitions. Run the entire lower-trust executor process tree with only its own workspace and required credentials. Do not mount Nora's home, WhatsApp session, personal vault or the board into that executor. The local seam probe demonstrates feasibility with synthetic commands.

`dispatch_once(spawn_fn=...)` is an internal, version-bound Python interface, not a supported stable plugin hook. Haven needs a small adapter around that seam, validated against the pinned source on upgrades. The probe does not implement admission authentication, crash-safe receipt handling, role-specific authorization or a production service. The built-in worker path is not automatically confined by selecting a container terminal backend.

For H1, restrict Nora's tools and postpone coding executors until H2. A Codex app-server worker is the preferred integration candidate for subscription-backed coding. Its login is separate from Hermes' native `openai-codex` provider. App-server lacks the Hermes `delegate_task`, `memory`, `session_search` and `todo` tools; use durable Kanban handoffs where supported rather than assuming feature parity. Do not copy the workstation's existing credentials or plugin configuration into an executor.

Keep task recovery independent of model reasoning. A deterministic, supervised control process can tick dispatch while Nora's model is unavailable. If using a systemd timer around CLI dispatch, disable gateway-embedded dispatch and verify worker scope/lifetime behavior on Ubuntu; do not run competing dispatch owners. Hermes documents the need for a user bus/linger for restart-safe worker scopes. This production setup is still H1–H2 work.

Hermes provides DB persistence, claim ownership, reclaim, quota requeues and cooldowns. Cron has a provider-window hold when a structured retry hint is available. An exhausted quota is distinct from revoked credentials or an unsupported model; terminal provider failures must remain parked for operator action. The tested fake provider returns HTTP 429; it does not prove the exact live Codex quota payload or account eligibility.

Task idempotency does not guarantee exactly-once external effects. Haven must bind results to the current run, retain checkpoints/artifacts and use operation keys for each deploy or outbound action. After a crash between an effect and its receipt, reconcile the actual target state before retrying. An ambiguous non-idempotent effect must wait for resolution. The shared board is coordination data, not an authorization boundary or a deployment approval authority.

For WhatsApp, the Baileys bridge remains the first candidate: dedicated number, explicit sender allowlist, groups disabled until configured. It uses the unofficial Web protocol; account restrictions and protocol breakage remain possible. Cloud API is a separate alternative requiring Meta business setup and public HTTPS ingress. Neither path was paired. Local STT can avoid an extra API subscription, but Czech audio quality, model size, RAM and CPU latency require an H1 measurement. A Codex subscription alone does not establish STT service access.

== Reproduction

Use a disposable checkout at the exact commit in `pins.json`. Commands below describe this audit, not a VPS installation. Do not point `HERMES_HOME` or `HERMES_RUNTIME_DIR` at an existing instance.

[source,bash]
----
# Run this in the Haven checkout before changing directories.
export HAVEN_ROOT="$PWD"
export HAVEN_RESEARCH="$HAVEN_ROOT/research/h0.1"
git clone --depth 1 --branch v0.22.5 https://github.com/NousResearch/hermes-agent.git /tmp/haven-h0.1-hermes-v0.22.5
cd /tmp/haven-h0.1-hermes-v0.22.5
test "$(git rev-parse HEAD)" = bf0203a794a07aac3ff764972ab9087baa4e4f4e
export HERMES_HOME=/tmp/haven-h0.1-state
export HERMES_RUNTIME_DIR=/tmp/haven-h0.1-runtime
python3 -m pm.build_env --source . --out /tmp/haven-h0.1-testenv --group dev --group test
----

All listed checkout, environment and container-store paths must be fresh and disposable. Change the example paths consistently if they already exist. The output destination must be fresh. PM selects the pinned Python and dependency lock. The test runner below strips credentials; all provider responses are synthetic.

[source,bash]
----
HERMES_PYTHON=/tmp/haven-h0.1-testenv/bin/python HERMES_E2E_STRICT_ACCEPTANCE=1 HERMES_TEST_FILE_RETRIES=0 \
  scripts/run_tests.sh -j 2 tests/e2e/core/kanban/test_kanban_rate_limit_review.py
----

That command fails on the unmodified release. Inspect the retained failure, then apply the exact patch:

[source,bash]
----
git apply --check "$HAVEN_RESEARCH/patches/upstream-117820.patch"
git apply "$HAVEN_RESEARCH/patches/upstream-117820.patch"
HERMES_PYTHON=/tmp/haven-h0.1-testenv/bin/python HERMES_E2E_STRICT_ACCEPTANCE=1 HERMES_TEST_FILE_RETRIES=0 \
  scripts/run_tests.sh -j 2 tests/e2e/core/kanban/test_kanban_rate_limit_review.py \
  tests/hermes_cli/test_kanban_db.py tests/hermes_cli/test_kanban_review_lifecycle.py \
  tests/hermes_cli/test_kanban_review_lifecycle_complete.py
----

For the WhatsApp connection tests, build a separate fresh environment with `--group dev --group test --extra sms`; the extra is how this release declares `aiohttp`. Merely installing the default test groups does not supply it. Exact test file selections are listed at the beginning of each retained log.

The two container probes use fixed dedicated Podman store paths under `/tmp/haven-h0.1-podman-*`; inspect those paths before use and do not run concurrent copies. Populate it with the digest from `pins.json`, then run each probe. They refuse a rootful runtime and use `--pull=never` while executing:

[source,bash]
----
mkdir -m 700 /tmp/haven-h0.1-podman-runtime
XDG_RUNTIME_DIR=/tmp/haven-h0.1-podman-runtime podman \
  --root /tmp/haven-h0.1-podman-storage --runroot /tmp/haven-h0.1-podman-run \
  --storage-driver vfs --cgroup-manager cgroupfs pull \
  docker.io/library/busybox@sha256:66a6306db78bf2dbf3487f293aa8d6990d8e506fdffab9cc43fe422becf886e4
python3 "$HAVEN_RESEARCH/probes/isolation.py"
env -i PATH=/usr/bin:/bin LANG=C.UTF-8 /tmp/haven-h0.1-testenv/bin/python \
  "$HAVEN_RESEARCH/probes/dispatch_isolation.py" /tmp/haven-h0.1-hermes-v0.22.5
----
