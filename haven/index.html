Haven documentation

Haven is a personal agent system built around Hermes, with Telegram as its first phone interface and WhatsApp as a future option. Text comes first; inbound Czech voice is later H1 work. The first deployment uses one Ubuntu VPS and bounded automation. Nora is the coordinator’s working name.

The local foundation is accepted through a fresh checkout: public sources, a private-instance template, configuration v1 validation and a documentation/check workflow. The existing Ubuntu pilot also has accepted private administration, independent model authentication, a supervised coordinator and owner-only Telegram text. Czech voice and off-site restore remain later H1 work; WhatsApp is deferred.

Start here

  • Local development: prepare the public checkout and a separate private instance.

  • Configuration v1: supported inputs, defaults, overrides and credential references.

  • Documentation and checks: build this site and run the public checks.

  • Architecture: controller/executor boundaries, recovery and milestone scope.

  • H1 prerequisites: what must be selected and verified before live operation.

  • VPS access and security: administrator keys, service account, firewall and verified configuration rollback.

  • Tailscale private administration: verified enrollment, policy, private-only SSH and guarded access recovery.

  • Repeatable bootstrap and restart: verified adoption of the secured pilot, restoration and post-boot access.

  • Supervised service and recovery: bounded native gateway, application rollback, restart-safe cron workers and recovery evidence.

  • Telegram private text: accepted owner enrollment, live replies, sender/command rejection and restart recovery.

  • Personal conversations and family sharing: deferred family design and access constraints.

  • Agent Platform assessment: exact community connector revision and local mocked compatibility results.

  • Earlier WhatsApp bridge preparation: retained optional Baileys procedure; inactive and not the selected path.

Evidence and limits

H0.1 established a technical path using synthetic providers and rootless-container probes. H0.2 verified the local repository/template workflow. H0.3 implements input validation; H0.4 records documentation and check acceptance. H0.5 verified the complete setup from a clean checkout and records the H1 handoff.

This site contains only public material. Personal configuration and instructions belong in each user’s separate private repository. Runtime sessions, credentials, databases and backups stay outside the public sources and build inputs.

The owner selected MIT and both repositories are published with their intended visibility; automatic local push checks replace unavailable GitHub Actions with the owner’s agreement. Original Haven material uses MIT. The retained Hermes patch and license keep their independent upstream attribution.
