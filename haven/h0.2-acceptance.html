H0.2 foundation acceptance

Verified locally on 2026-10-25 with Git 2.55.0 and a POSIX shell. The public and private working repositories use main and have no commits or remotes. License selection and GitHub name availability remain publication prerequisites.

This is the historical H0.2 snapshot, before the YAML contract existed. Current validation and migration instructions are in configuration v1.

Procedure and result

To test cloning without committing the owner’s work, the acceptance check copied Git-eligible public files into a temporary repository and made one synthetic fixture commit there. It cloned that snapshot with git clone --no-local under a fresh HOME, with system and global Git configuration disabled. The fixture repository and clone were deleted after verification.

The clone had no object alternates and no private repository dependency. The setup block was extracted from README and executed verbatim. All research checksums passed, and a separate private Git repository was created with an editable instance draft. Repeating setup rejected the existing destination and preserved a synthetic private instruction file.

Git ignore checks passed for representative dotenv files, Hermes/Codex authentication paths, sessions, credentials, backups, database files and private keys on both sides. The private YAML draft remained eligible for its private Git repository. The public clone stayed clean and contained no synthetic private marker.

Local documentation links, Python syntax and JSON were checked. The upstream patch and MIT notice matched the H0.1 originals byte-for-byte; the patch also matched its pinned SHA-256. Log redactions and the portable-probe change are recorded in provenance. The portable rootless isolation probe was rerun successfully; its result is retained in evidence.

Acceptance boundary

This establishes the local H0.2 repository/template workflow. No real credentials, paid inference or deployed services were used. The YAML file remains an illustrative draft. Schema validation, a documentation build and CI belong to H0.3–H0.4; complete H0 acceptance remains H0.5. Remote creation and publication remain pending the owner’s license decision and name checks.
