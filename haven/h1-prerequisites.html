H1 prerequisites and acceptance

H1 is accepted for the existing deterministic pilot on 2026-11-05; H1.10 records the combined results and remaining limits.

Publication is accepted, and administrator key access, the manual security baseline and configuration rollback were verified on Ubuntu 26.04 LTS on 2026-10-28. Tailscale private IPv4/IPv6 SSH, public-SSH cutover and narrow access fallback are verified. Bounded Ansible adoption, repeatability, access-file restoration and a controlled restart are also verified for the existing pilot. Native configuration, independent subscription login and one Hermes model request are verified. The bounded coordinator, native worker user bus, application rollback and restart/reboot recovery are verified. OS updates remain owner-deferred; coding dispatch stays disabled until H2. These are decisions and acceptance checks, not a complete clean-host installation procedure. H0.1 evidence retains its historical local/synthetic scope; WhatsApp remains unverified.

H1.6 owner-only Telegram text is accepted on the existing pilot: private enrollment, owner replies, denied-sender intake, blocked remote administration and enabled-service restart recovery are verified. The owner deferred WhatsApp, the second member and family sharing after confirming Agent Platform is unavailable on their account. The earlier Baileys/Agent Platform work remains inactive.

The owner subsequently selected H1.6.1 deterministic operations instead of ordinary AI chat. This profile is accepted with verified application rollback, idempotent repeat, restart and native execution guards. Four real owner messages produced two expected replies and two refusals without additional model calls or conversation rows; a live status reply after restart confirms transport recovery.

H1.8 adds verified prebuilt public Pages hosting, separately generated owner-only private runbooks and a static read-only operational snapshot. Private HTTPS, negative source-path checks, effective network filtering and release rollback are verified. The coordinator remains unchanged with no additional model calls. The guide records client/update acceptance and unperformed identity/IPv6 scenarios. The owner deferred H1.7 Czech voice on 2026-10-30; H1.9 off-site backup, isolated application recovery and external email delivery are accepted. The owner authorized completion of all remaining H1.10 steps on 2026-11-05. Fresh owner replies/refusals, process recovery, host reboot, backup/monitor health and private access passed. The final record explicitly reuses the unchanged H1.5 synthetic quota and H1.9 isolated application recovery/email evidence.

H0 handoff

H0.5 acceptance establishes the local foundation from a clean public clone with freshly installed dependencies. Configuration validation, instance creation and public documentation/checks work without the original private repository. The synthetic model and host are not deployment inputs, and the tested fixture commit is not a real Haven release.

Before reproducible deployment, establish the intended public-source revision and matching private configuration within the owner’s commit/remote authorization. Real source commits and separate public/private GitHub remotes now exist. The owner selected MIT; authenticated repository-name checks and publication are recorded in H1.1; automatic local push checks replace unavailable GitHub Actions with the owner’s agreement. These are distinct from the host/account acceptance below.

Accepted pilot inputs and remaining records

  • The existing host runs Ubuntu 26.04 LTS rather than the earlier 24.04 proposal. Its service/security baseline is verified; exact billing region and cost still need an instance record. A complete clean-host installation remains unverified.

  • Scaleway Object Storage and Healthchecks.io are selected and accepted in H1.9. Recovery access and the repository password must remain available independently of the VPS. Their independent storage is an owner record, not something inferred from a successful backup.

  • The Telegram bot and numeric owner are enrolled and accepted. Do not obtain a dedicated WhatsApp number for this pilot; family sharing and a later WhatsApp migration require separate implementation and acceptance.

  • H1.4/H1.5 verified the configured subscription model and independent service login. Current deterministic operations must not add model calls. Actual provider quota/revocation/refresh behavior remains outside the synthetic recovery evidence.

Technical work and evidence required

Area Acceptance to establish in H1

Host

Document admin access, updates, firewall and service account; restrict internal services through the selected private access mechanism.

Hermes

Install the exact candidate and patch, translate Haven configuration to native inputs, supervise with systemd and survive a restart.

Credentials

Protect service OAuth and Telegram credentials outside Git. Review failure handling without exposing or deliberately revoking a live account grant.

Messaging

Verify the one owner’s deterministic operations, sender rejection, blocked administration and restart recovery. Voice, WhatsApp and family access are deferred.

Recovery

Verify model-independent live recovery and review the pinned synthetic quota deferral/resumption and terminal-authentication evidence separately. Full executor recovery belongs to H2.

Backup

H1.9 accepts encrypted production snapshots, exact restore, clean isolated application reconstruction and real external alerts with Scaleway + Healthchecks.io. No second Telegram poller is started. New VPS/OS provisioning is outside the measured application recovery.

Documentation

Record the actually verified setup, interactive steps and recovery procedure without credentials, QR codes or session data.

Tailscale private administration, bounded Ansible host playbooks and the restic backup controller are implemented and verified for the pilot. SOPS with age is not implemented. H0.3 only checks credential-reference syntax; runtime protection and encrypted backup have their own milestone evidence.

The production controller/executor adapter belongs to H2. Deployment authorization and automatic rollback for the bounded demonstration target belong to H3. Passing foundation CI does not establish these runtime properties.
