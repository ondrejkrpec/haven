Documentation and public checks

H0.4 added an Antora site and shared checks. H1.1 uses automatic local pre-push checks as the primary pipeline because GitHub Actions is unavailable for the owner’s account. The build consumes public sources only. ADR 0002 records the choice; acceptance separates local verification from pending GitHub execution.

Prepare tools

Use Linux x86_64 or aarch64, Git 2.28+, sha256sum, Python 3.12+ with system IANA time-zone data, and Node.js 24 LTS with npm. Node.js 26 is also accepted for local work; CI selects 24. A VPS and live accounts are unnecessary. Create a virtual environment as described in configuration setup, then install the check dependencies:

python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes --only-binary=:all: -r requirements-dev.txt
npm ci --ignore-scripts --no-audit --no-fund
.venv/bin/python -m scripts.install_check_tools

Installation downloads public packages and release archives. requirements-dev.txt includes the runtime dependencies, Ruff, yamllint and pinned Ansible/core lint tools. It is compiled with the runtime lock as a constraint. package-lock.json fixes the npm dependency tree and archive integrity. No npm lifecycle scripts are needed. The binary installer verifies the archive SHA-256 from scripts/check-tools.json before extracting only the named Gitleaks/actionlint binary to ignored build/tools. It supports Linux x86_64 and aarch64; other operating systems need a separately verified setup before claiming parity.

Run the public checks

.venv/bin/python -m scripts.check

The command fails at the first unsuccessful check. It runs:

  • Ruff for Python import/name/syntax errors in maintained scripts and tests; historical H0.1 probes retain their original bytes.

  • Strict yamllint for Git-eligible YAML and the private template example; actionlint for workflow syntax, expressions and action inputs. ShellCheck/Pyflakes integration is disabled explicitly; workflow shell steps contain only literal tool invocations.

  • Ansible syntax checks and production-profile offline lint for the bounded host playbooks, using only the synthetic inventory. These do not contact a VPS.

  • Configuration validation for the public example and private template, followed by behavior tests including fail-closed host preconditions.

  • The retained H0.1 checksum manifest.

  • Gitleaks with default rules, full redaction and no inline allow markers. A disposable snapshot includes tracked and untracked Git-eligible candidates, excluding ignored local files. Available Git history is scanned with --all; an unborn repository explicitly skips only the history scan. CI fetches full history. No broad secret exclusions or baseline are configured.

  • The documentation build and offline source/generated-link checks, including HTML fragments.

  • git diff --check for tracked changes. New untracked files still need review before the first commit.

This does not validate your private instance, access any credentials, run Hermes or test upstream integrations. Explicit private validation remains a separate operation in the configuration guide. Pattern scanning cannot establish the absence of all sensitive data; review the exact publication candidates before publishing.

Build and view documentation

.venv/bin/python -m scripts.build_docs
.venv/bin/python -m scripts.check_links
.venv/bin/python -m http.server 8000 --bind 127.0.0.1 --directory build/site

Open http://127.0.0.1:8000/ and stop the local server with Ctrl-C. The last command serves only the generated site, bound to loopback. Alternatively, activate .venv and run npm run docs:build; npm uses python3 from your PATH.

Canonical guides remain in docs/, with navigation in docs/nav.adoc. The exporter creates a native Antora component in a temporary directory from Git-eligible .adoc guides and the retained H0.1 report. Relative link: file references become Antora xref: resources. The explicit ATTACHMENTS tuple in scripts/build_docs.py bounds downloadable public files; new targets must be declared. Raw Markdown attachments are downloads, not rendered site pages. Includes are unsupported, and escaping links or symlink inputs fail the build. Use repository-relative link: references in guides and native xref: references in navigation.

The exporter never discovers sibling repositories. It copies only selected public inputs and the Git-eligible local UI, initializes a temporary Git repository without commits, runs Antora with warning-level failure, then removes the temporary sources. Generated output replaces ignored build/site. Existing source paths, research evidence and working Git indexes are preserved. Once dependencies are installed, generation needs no network, external UI or private source. Antora 3.2 supports repositories without commits; no first-commit workaround is needed.

The repository-owned UI uses HTML/CSS and system fonts, with navigation, responsive layout, dark mode and a keyboard skip link. It requires no browser JavaScript. H1.8 adds a checked prebuilt Pages publisher and a separate, explicitly selected private Markdown build. No GitHub Actions publication workflow or private input is added to the public build.

Automatic local push pipeline

After preparing the tools, enable the versioned public hook in each checkout:

git config --local core.hooksPath .githooks

Commit your intended changes before pushing. The hook requires a clean checkout, including untracked source files, and the pushed commit must be the checked-out HEAD. It runs the complete scripts.check command and rejects the push on failure or a checkout change during checks. A successful receipt records the exact public revision, timestamp and result in Git metadata at haven-checks/last-success.json. It is not a tracked source or documentation input. Deletions and pushes with no new source revision do not run source checks.

For an instance created from the template, configure its independent private hook from the public checkout:

git -C ../haven-private config --local core.hooksPath .githooks
git -C ../haven-private config --local haven.publicRoot "$PWD"

Record the public HEAD in the private HAVEN_REVISION file and commit the instance before pushing. Its hook requires both checkouts to be clean and that revision to match the public HEAD. It reruns the public checks, explicitly validates the instance and scans private files and history with redacted Gitleaks output. Private receipts stay in that repository’s Git metadata; private source never enters the public build. Configure haven.publicRoot for the actual installation path; it is local Git configuration.

These are client-side checks on the configured checkouts. GitHub web edits and other clones do not automatically use them; every development clone needs setup. They are not a server-side permission boundary. An independent runner after VPS provisioning can add remote enforcement without depending on GitHub Actions. Do not use --no-verify as the normal publication path.

GitHub workflow and publication

GitHub Actions retains a manual workflow_dispatch definition for possible future use, without push/PR triggers. The owner selected the local pipeline after GitHub rejected the first job at account level before runner allocation. A successful Actions run is no longer required for H1.1 acceptance. No claim is made that GitHub-hosted checks passed.

The manual workflow selects Ubuntu 24.04, Python 3.12 and Node.js 24, with Actions pinned to full commits, read-only repository permissions and no instance secrets. Both source remotes are configured and MIT is selected. H1.1 records publication and local-pipeline acceptance. Hosting and private Tailscale documentation remain later work. H0.5 records the clean-checkout dependency installation.

Dependency updates and references

Update pins intentionally and rerun the full workflow. Regenerate the development lock while preserving runtime versions:

uv pip compile requirements-dev.in --python-version 3.12 --constraint requirements.txt \
  --generate-hashes --output-file requirements-dev.txt

For npm updates, change exact direct versions, regenerate package-lock.json, review dependency changes, then use npm ci --ignore-scripts. For binary updates, verify the upstream release archives/checksums and update both supported architectures. For Action updates, resolve the release tag to its full commit and review the release notes. Do not substitute mutable latest URLs for checked-in pins.

Primary references consulted on 2026-10-25: Antora 3.2 release notes, local sources, local UI bundles, failure thresholds, Gitleaks 8.30.1, actionlint 1.7.12, Ruff configuration, yamllint configuration and Actions security. Context7 was unavailable because its monthly quota was exhausted; official documentation and public package/release metadata were used instead.

The local pipeline follows Git’s official pre-push contract and repository-local hook configuration.
