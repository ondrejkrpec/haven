Architecture and implementation boundaries

Haven is intended to run a personal assistant on one Ubuntu VPS. Hermes supplies conversations, a durable Kanban board and scheduling. Telegram text is the first phone interface; WhatsApp and inbound Czech voice remain later work. The coordinator’s working name is Nora.

Current foundation

H0.1 established a candidate based on Hermes v0.22.5 plus an exact upstream patch. Local fake-provider tests and rootless container probes established feasibility. The report records versions and limits. H0.2 added this repository and the private-instance template; H0.3 adds configuration v1 validation. H1.5 now supplies a bounded pilot service.

H1.4 verifies the pinned core runtime, native subscription-provider configuration, independent service-owned OAuth and one request with no tools or fallback on the existing pilot. H1.5 adds native systemd supervision, a guarded no-tools profile and a required user bus for restart-safe cron workers. Coding dispatch remains disabled; the controller/executor adapter belongs to H2.

Keep common source, general instructions and public examples here. Each instance owns its configuration and personal instructions in a separate private repository. Runtime state, account sessions and databases require a future backup workflow outside Git.

The retained family design has separate personal conversations and explicitly shared family objects. It is deferred beyond the initial owner-only Telegram pilot. Future members need separate authenticated identities and private state; a narrow service must enforce ownership and family membership before returning data to the model. This access layer is not implemented by selecting Hermes profiles.

Controller and executor boundary

The trusted controller owns the durable board and admits narrowly scoped results bound to the current run. A worker and an independent reviewer will run as full isolated executor processes with only their workspace and required role-specific credentials. Neither receives Nora’s home, WhatsApp session, personal vault or direct access to the board.

The H0.1 dispatch_once(spawn_fn=…​) probe uses an internal, version-bound Hermes API. A small adapter with authenticated admission, role authorization and crash-safe receipts remains H2 work. Selecting a container terminal backend does not isolate Python, plugins or the rest of an agent process. Hermes profiles and task status do not enforce deployment authorization.

Recovery and bounded autonomy

Supervised deterministic dispatch must resume deferred work while Nora’s model is unavailable. Use one dispatch owner. Distinguish quota cooldowns from revoked credentials and terminal provider errors. Persistent tasks and idempotent intake do not guarantee exactly-once external effects; reconcile the target after uncertain outcomes before retrying.

Automatic deployment will initially be limited to the proposed haven-health demonstration service. An independent runner must enforce the permitted target, exact reviewed commit, health check and rollback policy. General production changes remain outside that permission.

Milestones

Milestone Remaining work

H0.3

Implemented locally: versioned YAML schema, validator, defaults/override rules and secret references. Runtime translation remains H1.

H0.4

Implemented locally: Antora documentation build, public check workflow, secret scan and link checks. Automatic local push checks replace unavailable GitHub Actions.

H0.5

Accepted locally: fresh public clone, newly installed dependencies, independent private instance and public build checks. See acceptance and H1 handoff.

H1.1

MIT selected; public/private GitHub remotes and source history exist. Local push checks replace unavailable Actions with the owner’s agreement.

H1

Host/private administration, model access, bounded service/recovery and owner-only Telegram text verified; Czech voice quality/latency, off-site backups and restore remain. WhatsApp and family sharing are deferred.

H2

Controller adapter, separate roles, full executor isolation, negative access tests and review lifecycle.

H3

Bounded automated repair and deployment with rollback.
